# 应用商店与自定义安装 设计

日期：2026-11-14　状态：待确认

## 目的

让主人在控制台里（或者对音箱说「小爱同学，安装……」）一键给音箱加能力，不用碰命令行。
装上的软件跑在腾讯云服务器上，能自动接到音箱，比如装完音乐库就能说「播放周杰伦」。

## 已经定下的

- **商店加自定义。** 主路径是精选应用商店，另有「高级」入口，可贴 docker-compose 或 GitHub 地址安装任意软件。
- **语音可以发起一切操作，不做二次确认。** 能叫醒「小爱同学」的人都能装和卸软件。这是主人的决定。
- **MCP 要支持各种形式。** 网络型（Streamable HTTP、SSE）已经可用；本地 stdio 型的 MCP 程序靠本设计在服务器上跑起来。

## 约束

- **服务器资源有限。** 4 核、3.6G 内存（空闲约 2.2G）、剩余 14G 硬盘，无显卡。上面已跑着闲鱼系统，不能被挤垮。
- **没有路由器权限。** 家里任何东西都不能被公网主动访问。所有给音箱用的服务都要放在公网，并且加鉴权。
- **控制台在 Docker 里运行。** 操作宿主机上的 Docker、nginx、certbot 需要额外的通道。

## 做法比较

**A. 把 Docker 套接字挂进控制台容器。** 最简单。但网页程序会直接拥有宿主机 root 权限，而且改 nginx、签证书还得再挂一堆目录，容器边界形同虚设。

**B. 宿主机上跑一个小「安装器」服务（推荐）。** 用 systemd 管理，只监听本机，只接受几种动作：安装商店应用、安装自定义 compose、启动、停止、卸载、读日志、查资源。控制台通过本机 HTTP 加共享密钥调用它。nginx 配置和证书由它在宿主机上处理。好处是权限集中在一个几百行、容易审查的程序里，网页程序被攻破也只能做这几种动作。

**C. 控制台 SSH 回宿主机执行命令。** 能用，但等于把一把万能钥匙放进网页程序，日志和错误也难以结构化。

选 B。代价是多一个进程要部署，由 `deploy/` 下的安装脚本一次性装好。注意：自定义 compose 本质上就能在服务器上跑任意程序，所以控制台密码等同于服务器的高权限，后续应加两步验证。

## 设计

**应用目录（catalog）。** 仓库里每个应用一个目录：`apps/<id>/app.yaml` 加 `docker-compose.yml`。`app.yaml` 描述：
- 名称、简介、图标；
- 占用估计，包括内存上限和磁盘；
- 安装时要用户填的参数，例如音乐库密码；
- 是否开放网页入口（子域名）；
- 装好后如何接到音箱：写入 `agent.yaml` 的哪一段，或者注册成 MCP 服务。

首批计划收录：
- **Navidrome：** 音乐库，接音箱的音乐功能；
- **RSSHub：** 新闻源，供新闻分析使用；
- **n8n：** 自动化，可以作为 MCP 服务；
- **stdio MCP 通用桥：** 见下文。

**网址与证书。** 每个带网页的应用用 `<应用>.speaker.xulangli.com.cn`。主人只需一次性在 DNSPod 加一条泛解析 `*.speaker` 指向服务器，之后每装一个应用，安装器自动写 nginx 配置并签发证书。

**资源保护。** 安装前对比应用声明的内存和当前空闲内存，不够就拒绝并说明原因。每个容器设置内存上限，只绑定 127.0.0.1，统一由 nginx 对外。

**stdio 型 MCP。** 在服务器上用一个桥接容器把 stdio 程序转换成 Streamable HTTP（例如 supergateway），只在服务器内部可访问。控制台再把它注册为一个外部 MCP 服务，地址走控制台自己的反向代理 `/mcp-bridge/<名字>`，复用设备 Token 鉴权。这样音箱从家里也能安全连上，这类程序也不用暴露到公网。

**语音工具。** 在控制台 MCP 里新增四个工具：
- `list_apps`：列出可装和已装的应用；
- `install_app`：只能装商店里的应用，参数取默认值或从对话中获得；
- `uninstall_app`
- `app_status`

语音不支持自定义 compose，因为没法说清一段配置。安装需要一两分钟：工具先回答「开始安装」，装完通过播报队列通知「Navidrome 装好了」。

**页面。** 新增「应用」页，分三块：
- 商店卡片，装好后显示「打开」「停止」「卸载」「日志」；
- 已安装列表；
- 高级：贴 compose 或 GitHub 地址。贴 GitHub 地址时，安装器只读取仓库根目录的 `docker-compose.yml`，不执行仓库里的任何脚本。

**卸载。** 停止并删除容器、nginx 配置和证书。数据卷默认保留，勾选「同时删除数据」才删。

## 不做

- **本地大模型：** 没有显卡、内存太小，跑不动有用的模型，继续用 API。
- **多台服务器、集群、自动扩容。**
- **应用自动升级：** 只提供手动的「更新」按钮。

## 留给实现时决定

- 安装器用什么语言（倾向 Python，和控制台一致）、监听端口和密钥存放位置；
- 具体的 nginx 模板写法；
- 每个应用的默认内存上限。

## 分期

1. **第一期：** 安装器、目录格式、Navidrome、RSSHub、「应用」页、子域名和证书自动化。
2. **第二期：** stdio MCP 桥、n8n、四个语音工具。
3. **第三期：** 自定义 compose 和 GitHub 安装。
